# 数据显示（data-board）— 内容与引擎扩展点清单

本包 `workshop/data-board/` 是**对局内的数据统计面板**：在左侧「同盟成员表」的**每一个玩家行**的头像右边贴一块
可收起的统计块（默认收起；展开后是「干员 / 协防 / 其他」三个选项卡 —— 干员页给每个干员算**综合 DPS**（含技能期与
他自己吃到的增益），并把**下场的那一行多留一个回合**；**「全量模拟」对局里再多一页「全量测试统计」**，含**逐盟约的
数值总结**与**增益提升占比的扇形图**）。

- `gameVersion` 0.3.1。**纯客户端包**：没有 `content`、没有服务端模块、**不携带任何素材**。
- **只读**：它不改动任何对局结果、不依赖任何引擎为本包新造的扩展点 —— 读到的数字与服务端校验用的是同一份。

## 1. 这个包往引擎里加了什么

- **一块贴在每个玩家行旁边的统计浮层**：面板挂在引擎自己渲染的官方槽 `screen.game.overlay`（对局屏根部的
  `.mod-host`）里，再用 DOM 找对局左侧成员表的每一个玩家行（`.team__row`），把统计块 `position: fixed` 贴到头像右边、
  与头像垂直居中。**每一台客户端都渲染所有人的**，所以人人都能看别人的。
- **一张「干员」页**：统计**当前在场**的干员（按 `chess` 记录的 `baseId` 归并 —— 重复个体与精锐化形态算同一个干员），
  每个干员列 名字 + 头像、生命 / 攻击 / 防御 / 阻挡、**上场次数**（只在每场战斗开始时 +1，
  联防 UNITE 是同一场战斗的后半段不重复计）、**上回合造成的伤害**、**累计造成的伤害**，再加一行速率：
  **本场 DPS / 预期 DPS / 技能 DPS**（会治疗的干员还有 HPS 三格）；行按累计伤害从高到低排（并列按阶级 / 名字）。
  * **本场 DPS**：正在演的那一场的实时读数（分母只算它出手的那段时间）；战斗刚停 / 休整期时回落到**上一场量到的那一份**
    （淡色，只留一个回合）。
  * **预期 DPS** 是**综合值**：常时 DPS × (1 − 技能覆盖率) + 技能期 DPS × 技能覆盖率 —— 覆盖率由技能时长
    （`duration` 秒，或弹药数 × 技能期攻击间隔）与充能时长（`spCost` ÷ 每秒技力回复；攻击回复按 `spCost` × 攻击间隔）
    推（稳态假设写在 `board.js` 的 `skillWindowOf()` 上）。能读到这一位**当前生效**的攻击力 / 攻击间隔
    （`unitStats()` 的 `cur`，**含他自己吃到的盟约 / 天赋 / 装备 / 正在跑的技能**）时用它，休整期退回纸面模型并标注。
  * **技能 DPS** 仍保留：一次技能期间的伤害 ÷ 技能时长，是「技能开着」那一档的参考。
  * **保留一回合**（业主 2026-10-15：「上回合的伤害记录什么的要保留一回合」）：干员**下场**之后那一行再多留一个回合
    （上面的数字是它最后一次在场上时的），**整整一个回合都不在场**才移除；不会无限攒，也不会在更晚的回合里复活。
- **「协防 / 其他」两个选项卡**：同样以选项卡列出对应数据，行与行之间用横线分隔。
- **「全量测试统计」页（仅「全量模拟」对局）**：公开帧带 `dev === true` 时才多出这一页（别模式一个字都不出现 —
  而「全量模拟」本身**只在本地端（回环 / 私网）生效**，服务端会拒掉非本地端的 `room.create.dev`，所以公网服务器上
  从外部连进来的浏览器**永远看不到这一页**；门禁三道闸见 `workshop/dev-ext/README.md` §3），
  三块：① **盟约加成 · 总和与来源** —— 已激活盟约（公开帧 `players[].bonds`）的层数 / 阶级、由这一行哪几块棋子供给
  （`chess.bonds` 反查）、盟约自己的描述（`bonds` 表），下面再接一块**逐盟约的数值总结**（数字**优先**取引擎真的落在
  那些成员身上的 `bond:*` 增益 —— `unitBuffs().mods` 翻成人话，如「【颂乐人偶】+50%攻击力、攻击速度+12」；本场一条都
  读不到时**退回盟约自己的数据口径** —— `bonds` 表那条记录的 `bb` 机器可读数字翻成同一套口径、明确标注
  「数据口径（未实测）」、认不出的数字键原样列出，绝不编造；「盟约加成合计」给的是**预计 DPS 提升**与它对预计 DPS 的
  **占比**，不是层数）；
  ② **本回合预计伤害与每秒伤害** —— 每个干员的**综合 DPS**（见上）之和 × 本回合战斗时长（时长优先取引擎 `b.start` 的
  `spec.timeLimit`，否则照引擎算法由 `config.rounds` 推），不在战斗里时退回纸面模型，另给本场实测已造成伤害；
  ③ **不同增益分别对总伤害的提升与占比** —— 用引擎战斗运行器新增的只读读数 `unitBuffs()` 取每条增益的 mods 与层数，
  **按比例分摊**：`unitStats()` 报的实测属性差（当前生效 − 裸基础）按每条增益的**声明幅度**（`mods` 折成攻击力 /
  攻击间隔两条通道，与 `server/sim/units.js` 的折算式同一条）分摊给各增益，再对每条算留一法提升 —— 类目与逐条各给
  **绝对提升与占比**，外加一张**扇形统计图**（一瓣一个类目，份额 = 这一类 ÷ **提升合计**）与实测合计（加算百分比那一档
  精确、乘算键为近似；它**不要求**与引擎的重算逐位吻合，所以**永远给得出数字**；`dmgDealtMul` 这类不落在攻击力上的增伤
  不在其中）。
- **联机时各看各的、也看得到别人**：本机那份逐单位伤害来自引擎战斗运行器的官方战果
  （`perPlayer[<我>].unitStats`）；**别人的那一行**由对方客户端经本包的 `roster` 通道广播过来。

## 2. 引擎侧需要的支持

本包**不新增任何引擎端口**，用的全是引擎已声明的能力：

| 用到的能力 | 说明 |
|---|---|
| 面板挂载槽 `screen.game.overlay` | 引擎自己渲染的官方槽（对局屏根部那块 `.mod-host`） |
| 组件改写 `game.hud.topBar`（`wrap`） | 顶栏每一帧都有最新的 `pub` / `priv` / `myId`，这一环把它们抄进模块内的表并通知面板重画 —— 不必等下一次 `m.public` 推送（那是**变化时才发**的，最长可能等一整个休整期） |
| 只读数据表 `ctx.data.get('chess')` / `('assets')` / `('bonds')` / `('config')` | 干员名字 / 阶级 / 基础数值 / `charId`、头像 URL；盟约描述（全量页的①）与回合战斗时长（全量页的②） |
| 包通道 `ctx.net`（通道 `roster`） | 把自己的统计广播给同房间的同包客户端 |
| 直接 import 引擎站点模块 `/js/battle/runner.js` | 读 `battleRunner` 的 `result` 事件（`screens/game.js` 订阅的是同一个）拿 `perPlayer[pid].unitStats`；全量页另读 `unitStats()` / `unitBuffs()` 两格只读读数（增益清单 + 折算式输入，不在任何网络帧里）。0.2.6 的那一刀在 `unitBuffs()` 的裸 `base` 上多带一格 `spRecovery`（其余九格照旧），本包拿它推技能覆盖率 —— 同样只读、不上线路 |

> 面板模块可以直接 import 引擎的**站点模块**（`docs/WORKSHOP.md` 有这一条），所以本包不需要引擎为它新造具名组件。
