# 模组管理（mod-manager）— 内容与引擎扩展点清单

本包 `workshop/mod-manager/` 是**工坊模组的开关界面**：在「选择模拟协议」顶栏（「干员调配」左边）加一个
「模组管理」浮层，把本房间要声明的模组列成一行行开关，逐个启用 / 停用。

- `gameVersion` 0.3.1。**纯客户端包**：没有 `content`、没有服务端模块、**不携带任何素材**。
- **状态不在包里**：「服务器声明了哪些包」（`available`）/「本房间点名了哪些」（`selected`）/
  「改名清单的唯一写入口」（`onSet`）都是引擎在每一帧交给改写链的 `props`；包只画，不改对局、不碰 store。

## 1. 这个包往引擎里加了什么

一个模块三条改写链（靠 `ctx.component` 区分这一帧自己在哪条链上）：

| 改写的引擎组件 | 位置 | 做了什么 |
|---|---|---|
| `lobby.modManager` | 大厅顶栏「干员调配」左边 | 引擎那一份默认什么都不画（`() => null`），这里画「模组管理」按钮 + 浮层：一行一个模组、右边一个开关。**这里能改**。一行写的是模组的**中文名**（该包 `pack.json` 的 `name`），包 id 留在这一行的 `title` 里。其中十格**整行不列出**（见下） |
| `lobby.modPicker` | 大厅创建框里旧的「本房间使用的模组」列表 | **把它收走**：返回的树里不放 `orig`，那张列表不再出现在创建框里（内容已搬进上面的浮层） |
| `room.modManager` | 房间顶栏「玩法说明」右边 | **只读**：集合在 `room.create` 那一刻就定死（协议里没有局内改集合的消息），所以只列「这一局真正跑哪几个包」，不给开关。显示名同上 |

三条口径来自引擎（`screens/lobby.js` 的 ModPicker / ModManagerSlot 注释）：

- **空 `selected` = 全选**：「本房间没声明集合」与「声明了全部」在服务端是同一件事，所以开关默认全开；
  要点名一个子集就先展开，于是每一次点击都是它字面上的意思。子集会被 `server/roomAssets.js` 逐包实体化 ——
  关掉的那一个这一局就不载入。
- **不列出自己**：关掉本包就是把这套界面一起关掉（`ctx.pack` 就是自己），所以它只参与状态判定、不进清单。
- **「全部停用」**（标题行右上那个总开关）= 只关掉**清单里列出来的**那些模组（写入 = 管理器自己 + 下面
  `LOCKED` 里的十格）：没显示、没有开关的模组保持启用。它与「把下面每一个都关掉」是同一个状态，默认关闭。

浮层的开合是本模块自己的视图状态（Preact 的 `useState` 放在一个**本地组件**里）：改写链每帧都重新求值，
组件实例由 Preact 按「同一位置同一类型」复用，所以开合状态活得比一帧长；勾选一变，引擎那边
（`store.roomMods.selected`）重画大厅，链跟着重算，开关与计数自动跟上。

**一行写的是模组的中文名，不是包 id。** 名字不抄第二份对照表：服务器已经把它发布在 `GET /mods/catalog.json`
（`server/modCatalog.js loadOnePack` 的 `name` —— 就是该包 `pack.json` 的 `name`，作者没写才回落包 id），
所以新加一个包不用改这个界面。目录取不到（离线 / 老服务器）时回落包 id；包 id 一直留在这一行的 `title` 里，
鼠标停一下就看得见。

**十格不列出**（分两批）：

- 业主 2026-10-18 的四格功能包：`dev-ext`（开发者功能扩展）/ `skin-picker`（时装切换）/
  `skin-supplement`（时装补充包）/ `operator-conflict`（干员冲突兼容）—— 关掉它们等于把那份功能一起关掉。
- 业主 2026-10-31 点名**从管理器里移除**的六格：`dimo-enemies`（特训敌人·涤墨）/ `enemy-ext`（新增敌人扩展）/
  `mode-recon`（模式扩展-重构模拟）/ `profession-expansion`（职业分支扩展）/ `server-ext`（服务器功能扩展）/
  `side-story`（故事集）—— 它们仍然随房间加载，只是不再占管理器的一行。

两批都与「管理器自己不列出自己」同一条口径：它们**不占清单里的一行**（大厅那份与房间那份都不列），只参与状态
判定与整份写入：它们恒为启用，永远写进「本房点名的清单」，连「全部停用」也只关掉清单里显示出来的那些，不会碰到
它们。判据是**包 id** 而不是显示名：显示名由包自己声明，改个名字不该把锁解掉。某一台服务器上没有那个包时
它自然不出现、也不会被写进清单（点名一个服务器没有的包会被判 `MOD_UNKNOWN`）。要改这份名单，改 `ui/manager.js`
顶部的 `LOCKED` 常量。

## 2. 引擎侧需要的支持

本包**不新增任何引擎端口**，用的全是引擎已声明的能力：

| 用到的能力 | 说明 |
|---|---|
| 面板挂载槽 `root.overlays` | 浮层挂在大厅根部的覆盖层 |
| 组件改写 `lobby.modManager` / `lobby.modPicker` / `room.modManager` | 三个引擎**已具名**的组件；一个组件只能被同一个面板改写一次 |
| 改写链的 `props` | `available` / `selected` / `onSet`（以及 `room.modManager` 的只读集合）都是引擎给的这一帧 props |
| `roomMods.js → room.create.modIds` | 「本房间声明哪些模组」这份状态由引擎保管，包只读它的投影 |
| `GET /mods/catalog.json` | 服务器发布的本机包目录（`server/modCatalog.js`）：**只读它一列** `id → name`，用来写清单里的中文名；不读它别的字段、不读它的文件清单 |
